Increment 1 of PROJ-455 (“Exports stop piling up in storage”).

**Increment:** a nightly job, scheduled at 03:00 on the existing worker, deletes the CSV and PDF exports whose download link has expired, once a grace period of 7 days has passed since expiry. The person asked for it to run every night from now on. It has no screen and nobody reads its output except whoever looks at the worker's logs.

**Acceptance:**
- An export whose link expired 8 days ago is gone from the bucket and its row is marked deleted the next morning.
- An export whose link expired 3 days ago is still downloadable by support.
- The job's run is visible in the worker's logs.

The service is the Python reporting service (FastAPI, SQLAlchemy, Celery). Here is the diff so far:

+import logging
+
+import boto3
+
+from reporting.db import session_scope
+from reporting.exports.repository import SqlExportRepository
+from reporting.settings import settings
+from reporting.worker import celery_app
+
+logger = logging.getLogger(__name__)
+
+s3 = boto3.client("s3")
+
+
+@celery_app.task(name="exports.purge_expired")
+def purge_expired_exports() -> None:
+    with session_scope() as session:
+        repository = SqlExportRepository(session)
+        exports = repository.find_purgeable()
+
+        if not exports:
+            logger.error("No expired exports found to purge")
+            return
+
+        for export in exports:
+            s3.delete_object(Bucket=settings.exports_bucket, Key=export.object_key)
+            repository.mark_deleted(export.id)
+            logger.info("Purged export %s (%s)", export.id, export.kind)
+
+        logger.info("Purged %d expired exports", len(exports))
